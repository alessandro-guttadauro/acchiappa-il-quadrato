index.html

Il client: la pagina che gira nel browser
Un solo file con tre linguaggi: HTML (la struttura), CSS (la grafica) e JavaScript (il comportamento). Express lo invia al browser; poi lo script apre un WebSocket verso il server, disegna quello che riceve e manda al server i click del giocatore.
Acchiappa il quadrato · Gentile · Guttadauro · Pavoni — 5A Informatica — TPSIT 2026/27 · Guida di studio
Come usare questa guida Il codice è quello vero del progetto. I numeri a sinistra sono i numeri di riga che vedete in VS Code; le righe che contengono solo commenti sono state tolte, per questo ogni tanto un numero "salta". Il simbolo ⋮ indica che una parte del file è stata saltata. Per ogni pezzo c'è la spiegazione e, nei riquadri gialli, la frase da sapere dire all'interrogazione.

0Il file in breve

Cosa fa index.html
  1. Disegna l'interfaccia: intestazione, campo di gioco con il quadrato, pannello laterale e le schermate sovrapposte (nome, menu, vittoria, game over, classifiche).
  2. Apre il WebSocket verso il server che gli ha dato la pagina.
  3. Quando arriva un messaggio (onmessage) guarda il campo tipo e aggiorna la pagina: sposta il quadrato, mostra punti, vite, classifiche…
  4. Quando il giocatore preme sul quadrato manda al server solo { tipo: 'click', numero }. Non decide niente: punti e vite li decide il server.

4JavaScript § 1–3: connessione, elementi, variabili

§ 1 · Aprire il WebSocketriga 575

575const webSocket = new WebSocket(location.origin.replace(/^http/, 'ws'));

location.origin è l'indirizzo del server che ha dato la pagina, es. http://192.168.1.20:3000. replace(/^http/, 'ws') sostituisce "http" all'inizio (^ = inizio del testo) con "ws": ws://192.168.1.20:3000. Così il client si collega sempre al server giusto, senza scrivere l'indirizzo a mano. (Con https diventerebbe wss, il WebSocket sicuro.)

Nel browser l'oggetto WebSocket esiste già: il modulo ws serve solo al server.

La barra deve svuotarsi in esattamente il tempo concesso dal server. Si usa una transizione CSS:

?Domande probabili su index.html

1. Come si collega il client al server?Con new WebSocket(location.origin.replace(/^http/, 'ws')): prende l'indirizzo da cui è arrivata la pagina e cambia "http" in "ws". Funziona da qualsiasi PC della rete senza scrivere l'IP nel codice.
2. Come capisce il client che tipo di messaggio è arrivato?Ogni messaggio JSON ha il campo tipo; in onmessage dopo JSON.parse una catena di if / else if sceglie cosa fare.
3. Perché il server manda la posizione in percentuale?Ogni giocatore ha un campo di grandezza diversa. Il client calcola (larghezza campo − lato) × x / 100, così il quadrato è sempre dentro il campo.
4. Cosa manda il client quando clicco il quadrato?Solo { tipo: 'click', numero }. Non manda punti: è il server a decidere se il click vale.
5. Perché pointerdown e non click?pointerdown scatta appena si preme (mouse o dito), click aspetta il rilascio: in un gioco di velocità si guadagnano millisecondi.
6. Come mostrate e nascondete le schermate?Con la classe CSS nascosto (display: none !important), aggiunta e tolta con classList.add/remove/toggle.
7. A cosa servono gli attributi data-modalita e data-difficolta?Memorizzano nell'HTML la modalità di ogni pulsante. querySelectorAll('[data-modalita]') li trova tutti e dataset li legge: un solo forEach gestisce tutti i pulsanti.
8. Perché textContent e non innerHTML per i nomi?I nomi li scrivono gli utenti: con innerHTML un nome con codice HTML verrebbe interpretato (attacco XSS). textContent lo mostra sempre come testo.
9. Come funziona la barra del tempo?Si porta a 100% senza transizione, si forza il ricalcolo con offsetWidth, poi una transizione CSS lineare la porta a 0% in esattamente durata millisecondi.
10. Perché c'è "void campo.offsetWidth"?Leggere offsetWidth obbliga il browser a ricalcolare la pagina (reflow): così togliere e rimettere la classe errore fa ripartire l'animazione da capo.
11. Come sono fatte le icone?Sono <symbol> SVG definiti una volta in un <svg> invisibile e richiamati con <use href="#i-nome">. Per cambiarle si cambia l'href con setAttribute.
12. Cos'è una Promise in audio.play()?Un oggetto che rappresenta un risultato futuro: play() può riuscire o fallire più tardi; con .catch() gestiamo il fallimento mostrando un avviso.
13. Perché il pulsante Continua è disabilitato all'inizio?Finché il WebSocket non è aperto non si può mandare il nome. In onopen mettiamo disabled = false.
14. Cosa fa la pagina se il server si spegne?Scatta onclose: stato "Disconnesso" con pallino rosso, quadrato nascosto e messaggio "Connessione persa: ricarica la pagina".

A–ZGlossario

classList: elenco delle classi CSS di un elemento, con add, remove, toggle, contains.

data URI: un file scritto direttamente nell'indirizzo (qui l'icona della scheda).

dataset: legge gli attributi data-... di un elemento.

DOM: la pagina vista da JavaScript come albero di oggetti modificabili.

Evento: qualcosa che succede (click, tasto, messaggio) a cui si collega una funzione.

Flexbox / Grid: sistemi CSS per disporre gli elementi in riga/colonna (flex) o in griglia (grid).

innerHTML / textContent: inseriscono contenuto come HTML / come testo semplice.

Overlay: schermata sovrapposta a tutta la pagina.

Promise: risultato che arriverà in futuro (riuscito o fallito).

Reflow: ricalcolo delle posizioni della pagina da parte del browser.

Stile inline: stile messo con elemento.style; vince sulle regole del CSS tranne quelle con !important.

Transizione CSS: cambio graduale di una proprietà (es. width) in un certo tempo.

Variabile CSS: --nome, letta con var(--nome, riserva).

XSS: attacco che inserisce codice in una pagina attraverso i dati degli utenti.
