server.js

Il "cervello" del gioco: gira su Node.js
Avvia il server HTTP con Express, ci aggancia il server WebSocket e contiene tutte le regole delle tre modalità. È l'unico arbitro: decide dove compare il quadrato, chi prende il punto, quante vite restano e quando finisce la partita.

Come usare questa guida Il codice è quello vero del progetto. I numeri a sinistra sono i numeri di riga che vedete in VS Code; le righe che contengono solo commenti sono state tolte, per questo ogni tanto un numero "salta". Il simbolo ⋮ indica che una parte del file è stata saltata. Per ogni pezzo c'è la spiegazione e, nei riquadri gialli, la frase da sapere dire all'interrogazione.

0Il file in breve

Cosa fa server.js, in cinque punti
  1. Server HTTP (Express) sulla porta 3000: invia la pagina index.html, la musica in streaming e due "API" in JSON.
  2. Server WebSocket (ws) agganciato allo stesso server HTTP: tiene una connessione sempre aperta con ogni browser e scambia messaggi JSON in tempo reale.
  3. Sfida multiplayer: un solo quadrato uguale per tutti, spostato da un setInterval ogni 1,2 s. Il primo click valido prende il punto; vince chi arriva a 10.
  4. Partite singole (Difficoltà e Infinita): ogni client ha la sua partita salvata in ws.partita, con il suo timer setTimeout; se il tempo scade si perde una vita.
  5. Record: a fine partita usa il nostro modulo record.js per salvare i 5 migliori punteggi e li manda a tutti.

4Express: il server HTTP

Ogni richiesta HTTP che arriva attraversa i middleware nell'ordine in cui sono scritti, finché uno non risponde:

L'applicazione e il middleware "logger"righe 105–113

105const app = express();
106
108app.use((req, res, next) => {
110 console.log(`[HTTP] ${req.method} ${req.url}`);
112 next();
113});

express() crea l'applicazione. app.use(funzione) registra un middleware: una funzione con tre parametri

  • req (request): la richiesta, con req.method (GET, POST…) e req.url (l'indirizzo chiesto);
  • res (response): la risposta da mandare;
  • next: funzione che passa la richiesta al middleware successivo.

Questo middleware non risponde: stampa una riga nel terminale (es. [HTTP] GET /musica) e chiama next(). Senza next() la richiesta resterebbe bloccata e il browser aspetterebbe per sempre.

Nel console.log c'è un template literal: testo tra backtick con ${...} per inserire il valore di una variabile.

Da ricordareMiddleware = funzione (req, res, next) eseguita per ogni richiesta, in ordine. next() passa al successivo.

File staticiriga 117

117app.use(express.static(path.join(__dirname, 'public')));

express.static è un middleware già pronto: se la richiesta corrisponde a un file della cartella public, lo invia. Quando il browser chiede / riceve public/index.html.

__dirname è la cartella in cui si trova server.js; path.join unisce i pezzi del percorso con il separatore giusto (/ su Mac e Linux, \ su Windows). Così il server funziona anche se viene avviato da un'altra cartella.

Rotta GET /musica: streamingrighe 120–136

120app.get('/musica', (req, res) => {
122 const fileMusica = path.join(__dirname, 'musica', 'sottofondo.wav');
124 if (fs.existsSync(fileMusica)) {
126 const info = fs.statSync(fileMusica);
128 res.writeHead(200, { 'Content-Type': 'audio/wav', 'Content-Length': info.size });
130 fs.createReadStream(fileMusica).pipe(res);
132 } else {
134 res.status(404).send('Musica non trovata');
135 }
136});

app.get('/musica', ...) crea una rotta: risponde solo alle richieste GET all'indirizzo /musica. La chiede il tag <audio src="/musica"> della pagina.

  1. fs.existsSync controlla che il file esista;
  2. fs.statSync legge le informazioni del file, tra cui size (dimensione in byte);
  3. res.writeHead(200, {...}) scrive il codice di stato 200 = OK e le intestazioni: il tipo (audio/wav) e la lunghezza;
  4. fs.createReadStream(file).pipe(res) apre uno stream: il file viene letto a pezzi (chunk) e ogni pezzo viene inviato subito, senza caricare tutto il file in memoria.

Se il file non c'è: res.status(404).send(...), codice 404 = non trovato.

Da ricordareLo stream legge e invia il file a pezzi: pipe() collega lo stream di lettura alla risposta.

5Server WebSocket ed eventi

Agganciare il WebSocket al server HTTPriga 173

173const ws_server = new Server({ server });

new Server({ server }) crea il server WebSocket usando il server HTTP di Express ({ server } è la forma breve di { server: server }). Risultato: HTTP e WebSocket usano la stessa porta 3000.

Come funziona: il browser manda una normale richiesta HTTP con l'intestazione Upgrade: websocket (handshake). Il server risponde 101 Switching Protocols e da quel momento la connessione TCP resta aperta e diventa bidirezionale (full-duplex): anche il server può mandare dati quando vuole.

Da ricordareHTTP: il client chiede e il server risponde, poi finisce. WebSocket: connessione sempre aperta, entrambi possono inviare in qualsiasi momento.

Evento message: lettura sicura del messaggio e CASO 1 (nome)righe 199–218

199ws.on('message', (dati) => {
201 let msg;
203 try {
205 msg = JSON.parse(dati);
206 } catch (errore) {
207 console.log(`[WS] messaggio non valido da ${ws.id}`);
208 return;
209 }
210
212 if (msg.tipo === 'nome') {
214 const nomePulito = String(msg.nome).trim().substring(0, 15);

ws.on('message', (dati) => {...}) scatta quando questo client invia qualcosa. I dati arrivano come testo; JSON.parse li trasforma in oggetto.

try/catch: se il testo non è JSON valido, JSON.parse lancerebbe un errore che, non gestito, farebbe crollare tutto il server (per tutti i giocatori). Con catch stampiamo un avviso e con return ignoriamo il messaggio.

Ogni messaggio ha un campo tipo che dice cosa fare. Caso "nome": puliamo il nome ricevuto

  • String() lo converte in testo (nel caso arrivi un numero o altro);
  • trim() toglie gli spazi all'inizio e alla fine;
  • substring(0, 15) tiene al massimo 15 caratteri (anche se qualcuno aggira il maxlength della pagina).

Se il nome è vuoto ('' è "falso"), || sceglie Giocatore 3 (con l'id).

Da ricordareMai fidarsi dei dati che arrivano dal client: si controllano e si puliscono sul server.

Eventi close ed errorrighe 266–279

266ws.on('close', () => {

close scatta quando il client si disconnette (pagina chiusa, ricaricata, rete persa). Due cose importanti:

  • fermaPartita(ws): annulla il timer della sua partita singola. Senza questa riga il setTimeout continuerebbe a scattare per un client che non c'è più.
  • inviaClassifica(): chi resta vede i connessi diminuire. Il modulo ws ha già tolto il client da ws_server.clients, quindi non compare più.

6Il ciclo della sfida

setInterval: il server "spinge" il quadratorighe 288–296

288setInterval(() => {
290 if (inPausa) return;
292 if (giocatoriSfida().length === 0) return;
294 nuovaPosizione();
296}, INTERVALLO_MS);

setInterval(funzione, 1200) esegue la funzione ogni 1200 ms, per sempre (finché il server è acceso). Ogni volta:

  • se siamo in pausa dopo una vittoria → return, non fa niente;
  • se nessuno sta giocando la sfida (giocatoriSfida().length === 0) → return, è inutile spostare il quadrato;
  • altrimenti chiama nuovaPosizione(), che sceglie un posto casuale e lo invia ai giocatori della sfida.

Questo è il vantaggio del WebSocket: è il server che decide quando mandare i dati (push), senza che il browser debba chiedere.

Da ricordaresetInterval = ripete ogni N ms. setTimeout = esegue una volta sola dopo N ms.

7Funzioni di invio e della sfida

Inviare a uno e inviare a tutti (broadcast)righe 304–318

304function inviaA(ws, messaggio) {
306 if (ws.readyState === ws.OPEN) ws.send(JSON.stringify(messaggio));
307}
308
310function inviaATutti(messaggio) {
312 const testo = JSON.stringify(messaggio);
314 ws_server.clients.forEach((client) => {
316 if (client.readyState === client.OPEN) client.send(testo);
317 });
318}

inviaA(ws, messaggio): invia a un solo client. Prima controlla ws.readyState === ws.OPEN: si invia solo se la connessione è aperta (potrebbe essere in chiusura). JSON.stringify trasforma l'oggetto in testo, perché sul WebSocket viaggia testo.

inviaATutti(messaggio): broadcast. ws_server.clients contiene tutti i client connessi; con forEach li scorriamo e inviamo a ognuno. Il testo JSON viene creato una sola volta prima del ciclo: è più efficiente che rifarlo per ogni client.

Inviare solo a chi gioca la sfidarighe 321–330

321function giocatoriSfida() {
323 return Array.from(ws_server.clients).filter((client) => client.modalita === 'sfida');
324}
325
327function inviaASfida(messaggio) {

ws_server.clients è un Set (un insieme senza doppioni), che non ha il metodo filter. Array.from lo trasforma in array, poi filter tiene solo i client con modalita === 'sfida'.

Da ricordareTre modi di inviare: a uno (inviaA), a tutti (inviaATutti), a un gruppo (inviaASfida, con filter).

La classifica della sfidarighe 333–345

333function listaClassifica() {
335 const lista = giocatoriSfida().map((client) => ({ id: client.id, nome: client.nome, colore: client.colore, punti: client.punti }));
337 lista.sort((a, b) => b.punti - a.punti);
338 return lista;
339}
340
342function inviaClassifica() {
344 inviaATutti({ tipo: 'classifica', connessi: ws_server.clients.size, giocatori: listaClassifica() });
345}

map trasforma ogni client in un oggetto semplice con solo i dati utili (id, nome, colore, punti): non possiamo mandare l'intero oggetto ws, che contiene la connessione.

sort((a, b) => b.punti - a.punti) ordina con una funzione di confronto: se il risultato è positivo b va prima di a. Quindi chi ha più punti va in cima (ordine decrescente).

inviaClassifica manda a tutti la lista e il numero di connessi (size = quanti elementi ha il Set).

Math.random() dà un numero decimale tra 0 (compreso) e 1 (escluso). Moltiplicato per 101 va da 0 a 100,99…; Math.floor arrotonda per difetto → un intero da 0 a 100.

Il server manda una percentuale e non dei pixel perché ogni giocatore ha uno schermo diverso: sarà il browser a trasformarla in pixel in base alla grandezza del suo campo.

quadrato.numero++ dà un numero nuovo a ogni quadrato: se arriva un click in ritardo riferito al quadrato vecchio, il numero non corrisponde e il click viene scartato.

colore: null significa "usa il giallo standard".

La formula della modalità infinitarighe 438–447

438function parametriInfinita(livello) {
440 const tempo = Math.max(380, Math.round(1500 * Math.pow(0.88, livello - 1)));
442 const dimensione = Math.max(34, 76 - (livello - 1) * 4);
444 const colore = COLORI_LIVELLO[(livello - 1) % COLORI_LIVELLO.length];
446 return { tempo, dimensione, colore };
447}

  • Dimensione: 76 − 4 × (livello − 1) px, mai sotto 34 px.
  • Colore: COLORI_LIVELLO[(livello − 1) % 10]; dal livello 11 i colori ricominciano.

prossimoQuadrato: mandare il quadrato e far partire il temporighe 450–478

450function prossimoQuadrato(ws) {
452 const p = ws.partita;
454 if (!p || p.finita) return;
456 const param = p.modalita === 'difficolta' ? DIFFICOLTA[p.difficolta] : parametriInfinita(p.livello);
458 p.numero++;
460 p.preso = false;
462 inviaA(ws, {
463 tipo: 'quadrato',
464 numero: p.numero,
466 x: Math.floor(Math.random() * 101),
468 y: Math.floor(Math.random() * 101),
470 dimensione: param.dimensione,
472 colore: param.colore || null,
474 durata: param.tempo,
475 });
477 p.timer = setTimeout(() => quadratoScaduto(ws), param.tempo);
478}
  1. Se la partita non c'è più (!p) o è finita → return. È un controllo di sicurezza: il timer potrebbe scattare dopo che il giocatore è uscito.
  2. param: i parametri vengono dalla tabella DIFFICOLTA oppure da parametriInfinita(livello). Entrambi hanno tempo e dimensione.
  3. Nuovo numero, quadrato "aperto" (preso = false).
  4. Invia solo a questo client il quadrato con posizione casuale, dimensione, colore e durata (il browser la usa per la barra del tempo). Nelle difficoltà param.colore non esiste (undefined), quindi || null manda null = giallo.
  5. p.timer = setTimeout(() => quadratoScaduto(ws), param.tempo): se nessuno annulla questo timer prima, il quadrato scade.
Da ricordareIl server manda il quadrato e avvia un setTimeout lungo quanto il tempo concesso. Se arriva il click prima, il timer viene annullato.

quadratoScaduto: si perde una vitarighe 481–497

481function quadratoScaduto(ws) {
482 const p = ws.partita;
484 if (!p || p.preso || p.finita) return;
486 p.preso = true;
487 p.vite--;
488 inviaA(ws, { tipo: 'mancato', numero: p.numero, vite: p.vite });
489 inviaStato(ws);

Guardia: se il quadrato è già stato preso o la partita è finita non fa niente. Altrimenti chiude il quadrato (preso = true, così un click arrivato in ritardo non vale più), toglie una vita con p.vite-- e invia mancato e lo stato aggiornato.

clickSingolo: il click in tempo e la formula di Tetrisrighe 500–529

500function clickSingolo(ws, numero) {
501 const p = ws.partita;
503 if (!p || p.finita || p.preso || numero !== p.numero) return;
504 p.preso = true;
506 clearTimeout(p.timer);
507 p.presi++;
509 let guadagno = 1;
511 const livelloPrima = p.livello;
513 if (p.modalita === 'infinita') {
515 guadagno = PUNTI_BASE * p.livello;
517 p.livello = Math.floor(p.presi / QUADRATI_PER_LIVELLO) + 1;
518 }
519 p.punti += guadagno;
520 inviaA(ws, { tipo: 'preso', numero: p.numero, id: ws.id, nome: ws.nome, colore: ws.colore, guadagno: guadagno });
522 if (p.livello > livelloPrima) {

529}

Guardia con quattro condizioni unite da || (basta che una sia vera per uscire): niente partita, partita finita, quadrato già chiuso, numero sbagliato.

Se il click vale: chiude il quadrato e clearTimeout(p.timer) annulla il timer, così quadratoScaduto non scatterà e non si perde la vita.

Punti: in modalità difficoltà ogni quadrato vale 1. In modalità infinita:

  • guadagno = 40 × livello, calcolato con il livello prima di aggiornarlo;
  • livello = Math.floor(presi / 10) + 1: con 0–9 quadrati presi livello 1, con 10–19 livello 2, e così via.

Esempio: 25 quadrati presi = 10 × 40 + 10 × 80 + 5 × 120 = 1800 punti, livello 3.

Confrontando livelloPrima con il nuovo livello capisce se si è saliti: in quel caso manda il messaggio livello con il colore nuovo. Infine stato aggiornato e prossimo quadrato dopo 350 ms.

Da ricordareclearTimeout annulla il timer che avrebbe tolto la vita. Livello = floor(presi / 10) + 1, punti = 40 × livello.

?Domande probabili su server.js

1. Che differenza c'è tra HTTP e WebSocket?In HTTP il client chiede, il server risponde e la comunicazione finisce. Il WebSocket è una connessione persistente e bidirezionale: dopo l'handshake resta aperta e anche il server può mandare dati quando vuole (es. il quadrato della sfida ogni 1,2 s o il messaggio "mancato").
2. Come fanno Express e ws a usare la stessa porta?app.listen restituisce il server HTTP e new Server({ server }) ci aggancia il WebSocket. Il browser apre il WebSocket con una richiesta HTTP Upgrade: websocket; il server risponde 101 Switching Protocols.
3. Cos'è un middleware? Perché il 404 è per ultimo?Una funzione (req, res, next) eseguita per ogni richiesta, nell'ordine in cui è registrata: o risponde o chiama next(). Il 404 è per ultimo perché deve rispondere solo se nessuno prima ha risposto.
4. Cosa fa fs.createReadStream(...).pipe(res)?Legge il file audio a pezzi e invia ogni pezzo subito nella risposta, senza caricare tutto il file in memoria.
5. Perché il JSON.parse è dentro un try/catch?Se arriva un testo non valido JSON.parse lancia un errore; senza catch il server si fermerebbe per tutti. Così il messaggio viene solo ignorato.
6. Dove salvate i dati di ogni giocatore?Dentro l'oggetto ws della sua connessione: ws.id, ws.nome, ws.colore, ws.modalita, ws.punti, ws.partita.
7. Come mandate un messaggio solo a chi gioca la sfida?giocatoriSfida() trasforma il Set ws_server.clients in array con Array.from e lo filtra con filter su modalita === 'sfida'; inviaASfida invia a ognuno.
8. Se due giocatori cliccano quasi insieme, chi prende il punto?Quello il cui messaggio arriva prima. Node gestisce gli eventi uno alla volta (event loop): il primo mette quadrato.preso = true, il secondo lo trova già preso.
9. Perché il quadrato ha un numero?Per scartare i click in ritardo: se il numero del click non è quello del quadrato attuale, il click è riferito a un quadrato vecchio e non vale.
10. Differenza tra setInterval e setTimeout nel vostro codice?setInterval (sfida) ripete ogni 1,2 s per sempre. setTimeout (partite singole) scatta una volta: lo usiamo come "conto alla rovescia" del quadrato e lo annulliamo con clearTimeout se il click arriva in tempo.
11. Come si perde una vita?In prossimoQuadrato parte un setTimeout di durata ms. Se scade prima del click, quadratoScaduto toglie una vita e invia mancato.
12. Perché in close chiamate fermaPartita?Per annullare il timer della partita singola: altrimenti continuerebbe a scattare per un client che non esiste più.
13. Come funziona la modalità infinita?Ogni 10 quadrati presi si sale di livello (floor(presi / 10) + 1); ogni quadrato vale 40 × livello; il tempo si moltiplica per 0,88 a ogni livello (minimo 380 ms), il lato cala di 4 px (minimo 34) e cambia il colore.
14. Perché controllate la difficoltà con Object.keys(...).includes?Il valore arriva dal client e potrebbe essere qualsiasi cosa: accettiamo solo facile, difficile o impossibile.
15. Perché decide tutto il server?Il codice del browser si può modificare; se decidesse il client si potrebbe barare. Il server è l'unico arbitro e il client mostra solo ciò che riceve.

A–ZGlossario

Broadcast: invio dello stesso messaggio a tutti i client connessi.

Callback: funzione passata a un'altra funzione, che la chiamerà più tardi (es. in app.listen, setTimeout).

Destrutturazione: const { Server } = ... prende una proprietà da un oggetto.

Event loop: il meccanismo con cui Node esegue un evento alla volta su un solo thread.

Handshake: la richiesta HTTP iniziale con cui si apre il WebSocket (risposta 101).

Hoisting: le dichiarazioni function si possono usare prima della riga in cui sono scritte.

JSON: formato di testo per rappresentare oggetti. stringify: oggetto → testo; parse: testo → oggetto.

Middleware: funzione (req, res, next) eseguita da Express per ogni richiesta.

Modulo: file di codice riutilizzabile, caricato con require.

Rotta: risposta a un metodo + indirizzo precisi, es. app.get('/musica', ...).

Set: insieme di valori senza doppioni; size = quanti sono.

Stream: flusso di dati letto e inviato a pezzi.

Ternario: condizione ? A : B, sceglie tra due valori.

Variabile d'ambiente: valore impostato dal sistema operativo, letto con process.env.
