record.js

Il nostro modulo: salva i migliori punteggi
Un modulo scritto da noi. Tiene in memoria le classifiche dei record (i 5 migliori punteggi di ogni modalità), le legge dal file record.json quando il server parte e le riscrive ogni volta che arriva un nuovo record, così non si perdono spegnendo il server.
Acchiappa il quadrato · Gentile · Guttadauro · Pavoni — 5A Informatica — TPSIT 2026/27 · Guida di studio
Come usare questa guida Il codice è quello vero del progetto. I numeri a sinistra sono i numeri di riga che vedete in VS Code; le righe che contengono solo commenti sono state tolte, per questo ogni tanto un numero "salta". Il simbolo ⋮ indica che una parte del file è stata saltata. Per ogni pezzo c'è la spiegazione e, nei riquadri gialli, la frase da sapere dire all'interrogazione.

0Il file in breve

Cosa fa record.js, in quattro punti
  1. Ha una variabile record con quattro classifiche: facile, difficile, impossibile, infinita.
  2. carica() legge il file record.json all'avvio (lettura sincrona).
  3. aggiungi() inserisce un risultato, riordina, tiene i primi 5 e dice in che posizione è arrivato; se è un record chiama salva(), che scrive il file (scrittura asincrona).
  4. Con module.exports rende disponibili a server.js solo tre funzioni: carica, aggiungi, elenco.

1Moduli e costanti

require, percorso del file e limiterighe 10–17

10const fs = require('fs');
12const path = require('path');
13
15const FILE_RECORD = path.join(__dirname, 'record.json');
17const MAX_RECORD = 5;

Il modulo usa due moduli interni di Node: fs (file system, per leggere e scrivere file) e path (per costruire i percorsi).

path.join(__dirname, 'record.json'): __dirname è la cartella di record.js, quindi il file dei record sta sempre accanto al modulo, da qualunque cartella si avvii il server.

MAX_RECORD = 5: in ogni classifica teniamo solo i 5 migliori. Scritto come costante, basta cambiarlo qui per tenerne di più.

2I dati in memoria

La variabile record e strutturaVuota()righe 20–25

20let record = strutturaVuota();
21
23function strutturaVuota() {
24 return { facile: [], difficile: [], impossibile: [], infinita: [] };
25}

record è dichiarata con let perché verrà riassegnata (da carica() e da aggiungi()). È dichiarata fuori dalle funzioni, quindi tutte le funzioni del modulo la vedono; ma non è esportata, quindi server.js non può toccarla direttamente: deve passare dalle funzioni.

strutturaVuota() restituisce un oggetto nuovo con quattro array vuoti. È una funzione (e non una costante) così ogni volta crea un oggetto nuovo.

Struttura dei dati (esempio inventato):

{ "facile": [ { "nome": "Luca", "punti": 31, "livello": 1, "presi": 31, "data": "20/11/2026" } ], "difficile": [], "impossibile": [], "infinita": [ { "nome": "Sara", "punti": 1800, "livello": 3, "presi": 25, "data": "21/11/2026" } ] }

È un oggetto che contiene array di oggetti: per leggere il primo record dell'infinita si scrive record.infinita[0].punti oppure record['infinita'][0].punti.

Da ricordareLe variabili e funzioni non esportate restano "private" dentro il modulo.

3carica(): lettura all'avvio

Leggere record.jsonrighe 28–40

28function carica() {
30 try {
32 const testo = fs.readFileSync(FILE_RECORD, 'utf8');
34 record = Object.assign(strutturaVuota(), JSON.parse(testo));
35 console.log('[RECORD] record caricati da record.json');
36 } catch (errore) {
37 record = strutturaVuota();
38 console.log('[RECORD] nessun record salvato: si parte da zero');
39 }
40}
  1. fs.readFileSync(FILE_RECORD, 'utf8') legge tutto il file come testo. È sincrona: il programma aspetta finché la lettura non è finita. Qui va bene, perché succede una volta sola all'avvio, prima che arrivino giocatori.
  2. JSON.parse(testo) trasforma il testo in oggetto.
  3. Object.assign(strutturaVuota(), datiLetti) parte dalla struttura vuota e ci copia sopra le proprietà lette dal file. Se nel file mancasse una lista (es. un file vecchio senza infinita), quella lista esisterebbe comunque, vuota.

try/catch: la prima volta il file non esiste e readFileSync lancia un errore; se il file è rovinato lo lancia JSON.parse. In entrambi i casi il catch riparte con le classifiche vuote, invece di far crollare il server.

Da ricordarereadFileSync è sincrona (blocca), ma si usa solo all'avvio. try/catch gestisce il file mancante o rovinato.

4aggiungi(): inserire un risultato

L'algoritmo passo per passorighe 43–59

43function aggiungi(classifica, risultato) {
45 if (risultato.punti <= 0) return -1;
47 const lista = record[classifica];
48 lista.push(risultato);
50 lista.sort((a, b) => b.punti - a.punti);
52 const posizione = lista.indexOf(risultato);
54 record[classifica] = lista.slice(0, MAX_RECORD);
56 if (posizione >= MAX_RECORD) return -1;
57 salva();
58 return posizione;
59}
  1. if (risultato.punti <= 0) return -1; una partita con 0 punti non è mai un record.
  2. record[classifica]: le parentesi quadre permettono di scegliere la lista con il nome contenuto in una variabile ('facile', 'infinita'…).
  3. push aggiunge il risultato in fondo alla lista.
  4. sort((a, b) => b.punti - a.punti) ordina dal punteggio più alto al più basso. L'ordinamento di JavaScript è stabile: a parità di punti l'ordine di prima resta, quindi chi c'era già resta davanti al nuovo.
  5. indexOf(risultato) trova la posizione del nuovo risultato (cerca proprio quell'oggetto).
  6. slice(0, MAX_RECORD) crea un nuovo array con gli elementi da 0 a 4: i primi 5. Il nuovo array sostituisce quello vecchio.
  7. Se la posizione è 5 o più, il risultato è stato tagliato fuori → -1, e non si salva niente. Altrimenti salva() e restituisce la posizione.

La posizione parte da 0 (primo posto): per questo la pagina scrive posizione + 1 ("Nuovo record: 1° posto!").

Da ricordarepush → sort decrescente → indexOf → slice(0, 5). Restituisce la posizione (0 = primo) oppure −1.
Esempio 1: il nuovo risultato entra in classifica

Classifica facile prima: 302520128 — arriva una partita da 22 punti.

dopo push: 30252012822

dopo sort: 30252220128 → indexOf = 2

dopo slice(0, 5): 30252220128 → restituisce 2, si salva, la pagina mostra "Nuovo record: 3° posto!"

Esempio 2: il nuovo risultato non basta

Stessa classifica, arriva una partita da 5 punti: dopo sort 3025201285 → indexOf = 5, che è ≥ 5: con slice viene tagliato fuori, la funzione restituisce −1 e il file non viene riscritto.

Perché è importante il controllo nel server. Se classifica fosse un nome che non esiste, record[classifica] sarebbe undefined e push darebbe errore. Non succede perché server.js passa solo 'infinita' o una difficoltà già controllata con Object.keys(DIFFICOLTA).includes(...).

5salva(): scrittura asincrona

Scrivere record.jsonrighe 62–69

62function salva() {
64 const testo = JSON.stringify(record, null, 2);
66 fs.writeFile(FILE_RECORD, testo, (errore) => {
67 if (errore) console.log('[RECORD] errore nel salvataggio: ' + errore.message);
68 });
69}

JSON.stringify(record, null, 2) trasforma l'oggetto in testo JSON. Il terzo parametro 2 indenta il testo con 2 spazi, così il file si legge bene anche aprendolo a mano (il secondo parametro, null, serve per filtri che non usiamo).

fs.writeFile(file, testo, callback) è asincrona: avvia la scrittura e il programma va subito avanti. Quando la scrittura finisce, Node chiama la callback con un eventuale errore (se è tutto ok vale null).

Da ricordarewriteFile è asincrona: il server continua a gestire i giocatori mentre il file viene scritto; la callback segnala la fine o un errore.
Sincrono: readFileSync

const testo = fs.readFileSync(...)
il programma si ferma finché il file non è letto, poi continua con il risultato.

Usato in carica(): una volta, all'avvio, quando non c'è ancora nessuno da far aspettare.

Asincrono: writeFile

fs.writeFile(..., (errore) => {...})
il programma non aspetta: continua subito, e la callback viene eseguita a scrittura finita.

Usato in salva(): durante il gioco, così nessuno sente rallentamenti.

6elenco() e module.exports

Esportare le funzionirighe 72–78

72function elenco() {
73 return record;
74}
75
78module.exports = { carica, aggiungi, elenco };

elenco() restituisce l'oggetto con tutte le classifiche: server.js lo manda ai client nel messaggio record e nella rotta /api/record.

module.exports è l'oggetto che il modulo "consegna" a chi fa require('./record'). Scriviamo { carica, aggiungi, elenco } (forma breve di { carica: carica, aggiungi: aggiungi, elenco: elenco }).

Quello che non è nell'oggetto resta privato: salva, strutturaVuota, la variabile record e le costanti. È un modo per proteggere i dati: da fuori si possono usare solo le tre funzioni pensate per farlo.

Una curiosità: elenco() restituisce un riferimento allo stesso oggetto, non una copia. Nel nostro progetto va bene perché server.js lo usa solo per inviarlo.

Da ricordaremodule.exports decide cosa vede chi fa require: il resto del modulo rimane privato.

?Domande probabili su record.js

1. Cos'è record.js?Un modulo personalizzato scritto da noi: esporta carica, aggiungi ed elenco con module.exports, e server.js lo importa con require('./record').
2. Perché nel require c'è ./ ?Indica un file del progetto, nella stessa cartella di server.js. Senza ./ Node cercherebbe un modulo chiamato record in node_modules.
3. Quali funzioni sono private e perché?salva e strutturaVuota (e la variabile record): non sono in module.exports, quindi server.js non le vede. Servono solo al funzionamento interno.
4. Perché readFileSync in carica e writeFile in salva?readFileSync blocca il programma, ma si usa una volta sola all'avvio. writeFile è asincrona: durante il gioco il server non si blocca mentre scrive.
5. Cosa succede la prima volta, quando record.json non esiste?readFileSync lancia un errore, il catch lo gestisce e si parte con le classifiche vuote. Il file viene creato al primo record, da salva().
6. A cosa serve Object.assign in carica?Unisce la struttura vuota con i dati letti: se nel file manca una lista, esiste comunque vuota.
7. Spiega l'algoritmo di aggiungi.push del risultato, sort decrescente per punti, indexOf per la posizione, slice(0, 5) per tenere i primi 5. Se la posizione è ≥ 5 restituisce −1, altrimenti salva e restituisce la posizione.
8. Cosa restituisce aggiungi e chi usa il valore?La posizione (0 = primo posto) o −1. finePartita la manda al client nel game_over (che mostra "Nuovo record: N° posto!") e, se è ≥ 0, invia i record aggiornati a tutti.
9. A parità di punti chi sta davanti?Chi c'era già: sort in JavaScript è stabile e il nuovo risultato era stato aggiunto in fondo con push.
10. Cosa fanno null e 2 in JSON.stringify(record, null, 2)?null: nessun filtro sulle proprietà; 2: indentazione di 2 spazi per rendere il file leggibile.
11. Perché un record con 0 punti viene scartato?Una partita persa senza prendere nessun quadrato non è un risultato da ricordare: la prima riga di aggiungi restituisce subito −1.

A–ZGlossario

Asincrono: l'operazione parte e il programma continua; il risultato arriva dopo, in una callback.

Callback: funzione chiamata quando un'operazione è finita (qui, la scrittura del file).

fs: modulo interno di Node per lavorare con i file.

indexOf: posizione di un elemento in un array (−1 se non c'è).

module.exports: ciò che un modulo rende disponibile a chi lo importa.

Object.assign(a, b): copia le proprietà di b dentro a.

slice(0, n): nuovo array con i primi n elementi (l'originale non cambia).

sort con funzione di confronto: b - a = decrescente, a - b = crescente.

Sincrono: il programma aspetta la fine dell'operazione prima di andare avanti.

try/catch: prova a eseguire un codice e, se c'è un errore, esegue il blocco catch invece di fermarsi.
